# Боты мессенджеров (Telegram и MAX)

## Назначение

Интеграция с ботами мессенджеров **Telegram** и **MAX** (VK). Любая переписка
пользователя с ботом попадает в интерфейс оператора (мессенджер), а ответ
оператора уходит обратно в мессенджер. Настройки вынесены в админку, чтобы не
захламлять торговую учётную запись.

## Каналы

| Канал | Значение `channel` | Библиотека |
| --- | --- | --- |
| Telegram | `telegram` | `aiogram` 3.x |
| MAX | `maks` | `maxapi` |

## Архитектура

Пакет [`app/bots/`](app/bots/):

- [`base.py`](app/bots/base.py) — абстрактный `BotAdapter` (интерфейс
  `run()` / `shutdown()` / `send_message()`) и структура `IncomingMessage`.
- [`telegram.py`](app/bots/telegram.py) — `TelegramAdapter` (long polling).
- [`max.py`](app/bots/max.py) — `MaxAdapter` (long polling, прямые сообщения).
- [`service.py`](app/bots/service.py) — оркестрация:
  - `BotManager` — реестр запущенных адаптеров (по каналу);
  - `store_incoming()` — входящее сообщение → создание/поиск `Chat` + `Message(in)`;
  - `deliver_outgoing()` — ответ оператора → адаптер → мессенджер;
  - `upsert_config()` / `get_configs()` — настройки ботов.

## Модель данных

- [`app/models/bot.py`](app/models/bot.py) — `BotConfig` (одна запись на канал:
  `channel`, `enabled`, `token`, `name`). Токен — секрет, хранится в БД и
  маскируется в интерфейсе.
- [`app/models/messaging.py`](app/models/messaging.py) — в `Chat` добавлен
  `external_id` (внешний id чата/пользователя в мессенджере, нужен для ответа).

Миграция: `alembic/versions/0a1b2c3d4e5f_bot_configs.py` (таблица `bot_configs`
+ колонка `chats.external_id`).

## Поток сообщений

1. **Входящее** (пользователь пишет боту): адаптер ловит сообщение →
   `store_incoming()` создаёт/находит `Chat` по `channel + external_id` и
   сохраняет `Message(direction="in")`. Чат появляется у оператора в мессенджере.
2. **Исходящее** (оператор отвечает в чате): `POST /api/chats/{id}/messages`
   сохраняет `Message(direction="out")` и, если чат внешний, вызывает
   `deliver_outgoing()` — сообщение уходит в мессенджер через активный адаптер.

## Настройки в админке

Страница `/admin/bots` (пункт «Боты» в меню админки):
- включение/выключение бота;
- токен (маскируется, пустое значение не перезаписывает сохранённый);
- отображаемое имя;
- индикатор статуса (активен / включён / выключен).

Изменения применяются **после перезапуска** сервиса (боты стартуют в lifespan
приложения). Маршруты — в [`app/web/admin.py`](app/web/admin.py), шаблон —
[`app/templates/admin/bots.html`](app/templates/admin/bots.html).

## Безопасность и логирование

- Токены не логируются и не отображаются в UI (маскируются).
- Каждое входящее сообщение и ошибки доставки логируются через
  [`app/core/logging.py`](app/core/logging.py) (логгер `app.bots`).
- Ошибки доставки не роняют основной поток и не мешают другим каналам.

## Ограничения

- **MAX** использует long polling официального API (ограничение ~2 RPS; вендор
  рекомендует webhook для production). Поддерживаются прямые сообщения
  «пользователь ↔ бот»; групповые чаты — в планах.
- Боты работают в том же контейнере, что и приложение (фоновые asyncio-задачи).

## Тесты

[`tests/test_bots.py`](tests/test_bots.py) покрывает: фабрику адаптеров
(`create_adapter`), поиск/создание чата, сохранение входящих, маршрутизацию
исходящих (через mock-адаптер), сохранение настроек (токен не стирается при
пустом поле) и рендер страницы админки.
