# Архитектура

## Технологический стек

| Слой | Технология | Обоснование |
| --- | --- | --- |
| Язык | Python 3.13 | Требование ТЗ; зрелая экосистема |
| Web-фреймворк | FastAPI | Современный, async, авто-генерация OpenAPI/Swagger |
| ORM | SQLAlchemy 2.0 (async) | Стандарт де-факто, строгая типизация |
| Драйвер БД | asyncpg | Быстрый нативный асинхронный драйвер PostgreSQL |
| СУБД | PostgreSQL 16 | Надёжность, JSONB, транзакции, миграции |
| Миграции | Alembic | Версионирование схемы БД |
| Валидация | Pydantic v2 | Схемы/DTO, валидация входных данных |
| Аутентификация | PyJWT + bcrypt | Стандартные проверенные решения |
| Шаблоны | Jinja2 | Server-side рендеринг интерфейса |
| Документация | Python-Markdown | Рендеринг Markdown в админке |
| Тесты | pytest + pytest-asyncio + httpx | Интеграционные тесты с PostgreSQL |
| Развёртывание | Docker + Docker Compose | Требование ТЗ: сервис + БД в контейнерах |

## Слоистая архитектура

```
app/
├── core/          # Конфигурация, БД, безопасность, зависимости, i18n
├── models/        # ORM-модели (справочники, документы, регистры, пользователи)
├── schemas/       # Pydantic-схемы (DTO)
├── services/      # Бизнес-логика (проведение, себестоимость, отчёты)
├── api/           # REST API (JSON)
├── web/           # Server-rendered интерфейс (Jinja2)
├── templates/     # HTML-шаблоны
├── static/        # CSS/JS
└── translations/  # Файлы переводов (RU/EN)
```

Направление зависимостей — строго сверху вниз:

```
web / api  →  services  →  models  →  core
```

Сервисы не знают о HTTP; модели не знают о бизнес-логике. Это позволяет тестировать
бизнес-логику изолированно (см. [testing](testing.md)).

## Поток обработки запроса

1. **HTTP** → маршрут в `app/api/*` или `app/web/*`.
2. **Аутентификация** → `app.core.deps` (JWT или cookie).
3. **Бизнес-логика** → `app/services/*`.
4. **Персистентность** → `app/models/*` через `app.core.database`.

## Модель данных (кратко)

- **Справочники** (`app/models/catalog/`): номенклатура, контрагенты (+договоры,
  расчётные счета), склады, фирмы, кассы, валюты (+курсы), единицы измерения,
  ставки НДС, типы цен.
- **Документы** (`app/models/document/`): единая таблица `documents` с
  дискриминатором `doc_type` и табличная часть `document_items`.
- **Регистры** (`app/models/registry.py`): партии (`stock_batches`), движения
  товаров (`stock_movements`), денег (`money_movements`), взаиморасчётов
  (`settlement_movements`).
- **Пользователи и права** (`app/models/users.py`): `users`, `roles`.
- **Константы** (`app/models/constants.py`): глобальные настройки.

Подробнее в [domain](domain.md).

## Регистровый подход

Вместо «таблицы на каждый документ» (как в 1С 7.7) используется **единая модель
документа + регистры движений**. Проведение документа порождает движения по
регистрам; остатки и отчёты строятся агрегацией регистров. Это:

- упрощает добавление новых видов документов (новый `DocType` + обработчик);
- даёт единый механизм отмены проведения (обратные движения);
- делает отчёты независимыми от структуры документов.

См. [domain.md#проведение-документа](domain.md).
