### Иерархия и автокод

`Nomenklatura` и `Kontragent` поддерживают иерархию (`parent_id`). Автоматическая
нумерация кодов реализована в `app/services/catalog_service.py`:
`next_nomenklatura_code()` и `next_kontragent_code()` (см. [reference](reference.md)).

## Перечисления

`app/models/enums.py` содержит все перечисления предметной области
(аналог «Перечисление» в 1С):

- `NomenklaturaVid` — товар/материал/продукция/тара/услуга;
- `KontragentVid` — юр./физ. лицо;
- `SkladTip` — оптовый/розничный/НТТ;
- `DocType` — виды документов;
- `DocSubtype` — наличный/кредит/реализация;
- `DocumentStatus` — непроведён/проведён/помечен на удаление;
- `CostMethod` — FIFO/LIFO/средняя;
- `RestockControl` — контроль остатков (по фирме/по складу/без контроля).

Перечисления хранятся как строки (колонки `String` с типом `Mapped[StrEnum]`) —
это упрощает миграции и расширение; сравнения `значение == Перечисление.X`
работают, т.к. `StrEnum` — подкласс `str`.

## Документы

Модель — `app/models/document/base_document.py`.

- `Document` — шапка: `doc_type`, `subtype`, номер, дата, статус, фирма,
  контрагент, договор, склад(ы), касса, валюта, сумма, НДС, комментарий,
  `extra` (JSONB для специфичных реквизитов).
- `DocumentItem` — табличная часть: номенклатура, количество, цена, сумма,
  ставка НДС, сумма НДС, склад (для многоскладских).

### Нумерация

`next_document_number()` (`app/services/document_service.py`) генерирует номер
вида `{префикс_ИБ}{код_типа}-NNNNN`, где префикс задаётся константой `prefix_ib`.

## Регистры

`app/models/registry.py`. Проведение порождает движения, остатки — агрегация.

| Регистр | Назначение |
| --- | --- |
| `StockBatch` | Партия (остаток номенклатуры на складе с себестоимостью) |
| `StockMovement` | Движение товара (+приход / −расход) |
| `MoneyMovement` | Движение денег по кассе/счёту (с привязкой к фирме) |
| `SettlementMovement` | Движение по взаиморасчётам с контрагентами (с привязкой к фирме) |
| `AccountingEntry` | Бухгалтерские проводки (автоматически при проведении) |

Для многофирменного учёта `MoneyMovement` и `SettlementMovement` содержат
`firma_id`; отчёты по деньгам/взаиморасчётам принимают фильтр по фирме.

## Проведение документа

Проведение — центральная операция (`post_document` в
`app/services/document_service.py`):

1. Проверка статуса (нельзя проводить помеченный на удаление).
2. **Контроль остатков** — если настроен (`restock_control`), для расхода
   проверяется достаточность остатков (по складу или по фирме).
3. **Формирование движений**:
   - приход (`PRIHOD`, `OPRIHODOVANIE`, `VVOD_OSTATKOV`) → создание партии;
   - расход (`RASHOD`, `SPISANIE`) → списание партий по методу себестоимости;
   - перемещение → списание с отправителя + оприходование получателю;
   - деньги/взаиморасчёты → соответствующие регистры.
4. Установка статуса «Проведён» + `posted_at`.

## Партионный учёт и себестоимость

Реализован в `app/services/stock_service.py`:

- `create_incoming()` — приход формирует партию с себестоимостью `unit_cost`;
- `consume_batches()` — списание по методу (`CostMethod`):
  - **FIFO** — списание старейших партий;
  - **LIFO** — списание новейших партий;
  - **средняя** — списание по средневзвешенной себестоимости.
- остатки — `get_balance()` / `get_balances()` (сумма остатков партий).

Метод списания задаётся константой `cost_method`.

## Взаиморасчёты

Знак суммы в `SettlementMovement.amount`: **положительное = контрагент должен
нам**, отрицательное = мы должны контрагенту. Продажа в кредит увеличивает долг
контрагента (+сумма), приход в кредит/на реализацию — нашу задолженность
(−сумма), ПКО уменьшает долг контрагента, РКО/ПП уменьшает нашу задолженность.

## Бухгалтерские проводки

При проведении автоматически формируются проводки (`AccountingEntry`,
`_apply_accounting` в `app/services/document_service.py`):

- `PRIHOD` — Дт 41 / Кт 60; `VOZVRAT` — Дт 41 / Кт 62;
- `RASHOD` — Дт 62 / Кт 90.1 (выручка) и Дт 90.2 / Кт 41 (себестоимость);
- `SPISANIE` — Дт 91.2 / Кт 41; `OPRIHODOVANIE` — Дт 41 / Кт 91.1;
- `INVENTARIZACIYA` — излишек Дт 41 / Кт 91.1, недостача Дт 94 / Кт 41;
- `VVOD_OSTATKOV` — Дт 41 / Кт 00; `VVOD_OSTATKOV_DENEG` — Дт 50 / Кт 00;
- `PEREOCENKA` — дооценка Дт 41 / Кт 91.1, уценка Дт 91.2 / Кт 41;
- ПКО — Дт 50 / Кт 62; РКО — Дт 62 / Кт 50; ПП — Дт 60 / Кт 51.
